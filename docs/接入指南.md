# API-free 使用与接入指南

> 2026-10-07 实测整理。文中「✅ 实测」的结论都是在本机真跑过的，未验证的会明确标注。

---

## 1. 面板怎么用

**启动：双击项目根目录的 `start.bat`**（= `panel/start.ps1`）。它会启动面板、等它就绪、再由面板把四个服务拉起来（这样服务归面板托管、崩溃自动拉起），最后打印状态表并打开浏览器。已在跑的会跳过，可重复执行。
**停止：双击 `stop.bat`**（先停四个服务，再关面板）。

手动启动的话是 `panel\bin\panel.exe`——注意**必须从 panel 目录启动**，它的 `data/`、`ui/dist/`、各服务目录都是相对路径，换目录会另建一套空数据。面板默认监听 `127.0.0.1:9000`，浏览器打开 <http://127.0.0.1:9000>。

| 页面 | 用途 |
|---|---|
| 总览 | 四张服务卡片（账号数/可用/冷却、积分、模型数、今日 token、活动与任务完成度、端口、启停开关）、30 天用量趋势、面板事件流 |
| 服务 ×4 | 每服务一个详情页：账号池（登录授权/签到/积分/任务/批量操作）、模型、用量、日志、**接入**、设置（在线改配置）+ 右上「打开原面板」 |
| 统计 | 跨服务用量聚合：今日/30 天、对比趋势、服务占比、逐日明细 |
| 日志 | 面板事件流（启停/崩溃拉起/统计拉取）+ 各服务运行日志 |
| 设置 | 面板偏好、服务注册表（含每家的**鉴权来源**：密钥文件与字段）、进程监督、关于 |

### 每个服务的「接入」页签（拿到密钥与调用方式就靠它）

打开服务 → 「接入」页签，四块内容：

1. **连接信息**：地址可在「经面板（推荐）」与「直连服务」之间切换，各带复制；下面就是 **API Key**（默认脱敏成 `sk-cline…`，点「显示」看全文、点「复制」进剪贴板——明文接口只对本机开放）；再下面是协议（OpenAI / Anthropic）与端口。
2. **模型**：下拉选一个模型（默认带出该服务的默认模型），列表来自该服务的 `/v1/models`。
3. **客户端接入代码**：cURL / Python / Node / Anthropic（仅 cline）/ 环境变量 五个 tab，代码按上面选的地址与模型实时生成，`复制这段代码` 一键拿走。选「经面板」时密钥位是 `panel` 这样的占位——**不用解锁明文就能直接跑**。
4. **接入须知 + 一键自检**：自检发一条最小请求（`max_tokens=64`），直接显示 HTTP 状态、耗时和回复或上游错误原文。

> 服务没在运行时，这个页签照样显示地址与密钥（只有模型列表会写明「服务未运行」）——要配客户端时它照样能用。


要点：

- **开关 = 真·进程启停**。停止是杀进程树；面板托管的服务崩溃会指数退避自动拉起（30s 起、最长 10 分钟）；面板外部起的实例会被「收编」，掉线时接管拉起。
- 服务详情页的「设置」页签可以直接看/改该服务的配置（改前注意哪些字段需要重启）。
- 面板**没有**做开机自启，重启机器后需要手动启动面板和四个服务（总览页逐个点开关即可）。

## 2. 接入其他 Agent：两个入口

### 入口 A：经面板代理（推荐）

```
http://127.0.0.1:9000/api/svc/<服务id>/v1
```

- `<服务id>`：`workbuddy` / `qoder` / `cline` / `cmdgo`
- **客户端 api_key 随便填**（例如 `panel`）。面板会把它**覆盖**成该服务的真实密钥，所以每个 Agent 里都不用存真钥。✅ 实测
- 要求面板在运行（面板再要求该服务在运行）。

### 入口 B：直连服务端口

```
http://127.0.0.1:<端口>/v1        # 需要带上该服务自己的 api_key
```

| 服务 | 端口 | 密钥位置（面板「设置」页的鉴权来源列同此；**面板「接入」页签可直接查看/复制**） |
|---|---|---|
| WorkBuddy-free | 7863 | `workbuddy-free-main/config.json` → `api_key` |
| Qoder-free | 8210 | `Qoder-free-main/config.json` → `api_key` |
| Cline-free | 8787 | `cline-free-main/.env.local` → `API_KEY` |
| cmdgo-bridge | 8014 | `~/.cmdgo-bridge/config.json` → `apiKey` |

直连的好处是面板没跑也能用；代价是没有进程监督与崩溃拉起。

> 面板**没有**「一个 base URL + 一个 key 调四家」的聚合入口——那是计划里预留、尚未实现的部分。四家仍是四个独立入口。

## 4. 各客户端的接法

### 4.1 OpenAI SDK（Python）

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:9000/api/svc/cline/v1",  # 换 /workbuddy/ 就是另一家
    api_key="panel",                                    # 随便填，面板会覆盖
)
r = client.chat.completions.create(
    model="deepseek/deepseek-v4-flash",                 # 从该服务 /v1/models 里取
    messages=[{"role": "user", "content": "你好"}],
)
print(r.choices[0].message.content)
```

### 4.2 curl

```bash
curl http://127.0.0.1:9000/api/svc/cline/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek/deepseek-v4-flash","messages":[{"role":"user","content":"你好"}],"max_tokens":64}'
```

流式（`"stream":true`）已实测：返回 `Content-Type: text/event-stream` + chunked，逐条 `data:` 分片。✅

### 4.3 OpenAI 兼容客户端（Cline、Continue、Cursor、Cherry Studio、ChatBox…）

填两个字段 + 选模型：

- **Base URL / API 地址**：`http://127.0.0.1:9000/api/svc/cline/v1`（或直连 `http://127.0.0.1:8787/v1` + 真 key）
- **API Key**：走面板代理就随便填
- **Model**：从 `/v1/models` 拿，例如 `deepseek/deepseek-v4-flash`

### 4.4 Claude Code（Anthropic 协议）

只有 **cline** 提供 `/v1/messages`。PowerShell：

```powershell
$env:ANTHROPIC_BASE_URL="http://127.0.0.1:9000/api/svc/cline"
$env:ANTHROPIC_AUTH_TOKEN="panel"
$env:ANTHROPIC_MODEL="deepseek/deepseek-v4-flash"     # 指到 cline 的模型 id
claude
```

cmd 用户用 `set ANTHROPIC_BASE_URL=...`。

> ⚠️ 协议本身已实测通过（`/v1/messages` 返回标准 Anthropic 格式），但**没在 Claude Code 里端到端跑过**。Claude Code 默认会发它自己的模型名（claude-sonnet-4-5 之类），所以要显式设 `ANTHROPIC_MODEL` 指到 cline 的模型 id，否则可能被上游拒绝——这一点请以实际运行为准。

## 5. 几个实测出来的坑

1. **workbuddy 是推理模型**：`max_tokens` 给小了（例如 8），token 会全被思考吃掉，`content` 返回空字符串，思考内容在 `reasoning_content` 里。要留够预算（实测 200 就正常出话术）。
2. **cline 的 `cline-free/deepseek-v4.1-flash` 是上游已下架的内建项**（会报 model not found）。用 `deepseek/deepseek-v4-flash`。
3. **qoder / cmdgo 现在调不通不是配置问题**，是账号/授权没准备好（见 §3）。qoder 在面板 qoder 服务页「账号」页签登录；cmdgo 的 OAuth 回调走本机 5959-5968 端口。
4. **Windows 下 curl 里带中文会乱码**：cmd/PowerShell 把 `-d '{"content":"你好"}'` 的编码搞坏了（实测服务端收到的就是乱码，模型会答「我只收到了''」）。要发中文就写成文件用 `-d @body.json`（文件存 UTF-8），或先拿英文验证通路。
5. **安全**：面板代理会注入真实密钥，所以 `:9000` 不要暴露到公网；另外 workbuddy 监听 `0.0.0.0:7863`（局域网可达），另外三家只听 `127.0.0.1`。要让局域网里的 Agent 用，得显式 `panel.exe -addr 0.0.0.0:9000`，且请自行确认网络环境可信。

## 6. 排障速查

| 现象 | 先看哪里 |
|---|---|
| 调用报连接失败 | 面板在跑吗（<http://127.0.0.1:9000/api/health>）；目标服务在跑吗（总览卡片/`/api/services`） |
| 401 / invalid api key | 直连时才可能出现：密钥文件字段对不对（面板「设置」页的鉴权来源列） |
| 模型 not found | 用 `/v1/models` 里真实存在的 id；cline 去「模型库」启用；workbuddy 注意 `cn:` 前缀 |
| 没有可用账号 | 服务详情页「账号」页签登录账号 |
| 响应很慢 | 各服务上游波动；面板「日志」页看运行日志，统计页看失败数 |
