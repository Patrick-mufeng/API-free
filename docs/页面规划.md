# API-free 统一面板 · 页面规划

> 2026-10-06。先定页面与内容，再回到 demo。本文档盘点**四个服务原面板的真实功能**，映射到统一面板的页面结构中，保证「功能全部搬迁」不漏项。
> 风格沿用已确认的 Apple 玻璃磨砂（页面结构以本文档为准，风格细节后调）。

---

## 1. 页面地图

```
统一面板
├── 总览            # 跨服务仪表：KPI、趋势、服务卡、最近请求
├── 服务 ×4         # 每个服务一个详情页，统一页签结构（见 §3）
│   ├── Qoder-free
│   ├── workbuddy-free
│   ├── cline-free
│   └── cmdgo-bridge
├── 统计            # 跨服务聚合统计（对比、排名、明细）
├── 日志            # 跨服务请求流水（聚合实时日志）
└── 设置            # 面板自身：服务注册表、面板偏好
```

左侧导航栏：**总览 / 服务（展开四项）/ 统计 / 日志 / 设置**。
「服务」四个子项在导航中直接展开（Qoder、WorkBuddy、Cline、cmdgo），点哪个进哪个服务详情页。

## 2. 总览页

**目的**：打开面板第一眼回答三个问题——服务都活着吗？今天用了多少？有没有异常（冷却/错误）？

| 区块 | 内容 | 数据来源 |
|---|---|---|
| KPI 行 | 今日 Tokens（合计 + 较昨日）· 今日请求 · 活跃服务 x/4 · 冷却中模型数 | 面板自身聚合库（各服务统计拉取） |
| 用量趋势 | 近 30 天每日 token 面积图，可切换「全部 / 按服务分线」 | 面板聚合库 |
| 服务状态卡 ×4 | 服务名 · 进程状态（运行中/已停止/启动中/异常）· 今日用量 · 开关（真·启停）· 「进入服务 →」链接 | 面板监督器 + 各服务 |
| 最近请求 | 跨服务请求流水（时间/模型/状态码/耗时/tokens/所属服务），最近 8 条 | 各服务日志拉取 |
| 异常提醒条 | 有内容才显示：X 个模型冷却中（预计恢复时间）· X 次连续失败 · 某服务离线 | 各服务状态 |

**全局状态**：某服务已停止时，其 KPI/图表位置显示「-」并置灰，不显示为 0（0 和"没数据"是两回事）。

## 3. 服务详情页（统一模板 + 各服务差异）

### 3.1 公共部分（四个服务都有）

| 区块 | 内容 |
|---|---|
| 服务信息头 | 服务名 · 进程状态徽标（运行中/已停止/启动中/异常+自动重启次数）· 端口 · 启动方式 · 开关 · 重启按钮 ·「打开原面板」备用链接 |
| 页签栏 | **账号 · 模型 · 用量 · 日志 · 设置**（+ 各服务特有页签，见 3.3） |

### 3.2 公共页签内容

**账号**
- 账号列表：每个账号一行/一卡，字段随服务不同（见 3.3）
- 添加账号：各服务都是「发起授权 → 浏览器登录 → 轮询结果 → 入池」，统一做成弹窗式登录流程（显示授权链接/打开按钮/等待状态/成功失败）
- 账号操作：删除 / 启停（各服务支持范围不同）

**模型**
- 模型清单（各服务字段不同，见 3.3）
- 模型级操作：启用/禁用/设默认/检测（仅 cline 有全套）

**用量**
- 该服务自己的统计口径展示（面板聚合库 + 直接读该服务统计接口，以服务自身统计为准）
- 图形：按天趋势 + 按模型/账号细分

**日志**
- 请求日志表：时间/模型/状态/耗时/tokens（workbuddy 另有 TTFB、tok/s）
- 运行日志（服务 stdout）：按频道筛选
- 实时刷新（SSE/轮询）、筛选、单条详情

**设置**
- 在线编辑该服务的配置文件（表单化 + 原文对照）
- 标注哪些字段热生效、哪些需重启（workbuddy 配置语义已明确，照搬）

## 4. 统计中心（跨服务）

| 区块 | 内容 | 说明 |
|---|---|---|
| 对比趋势 | 四服务 token 趋势叠加图（可切换堆叠/分线），时间范围切换 | 数据源：面板聚合库（每 5 分钟拉取各服务统计落 SQLite） |
| 排行 | 按模型 TOP（跨服务同名模型合并标注来源）· 按服务占比 | |
| 明细表 | 日期 × 服务 × 模型的 tokens/请求数表格，可排序、导出 CSV | |
| 口径说明 | 明确标注：各服务自身统计为准，聚合为面板拉取口径；cmdgo 为补丁口径 | 避免数字"看起来对不上"的困惑 |

---

## 5. 日志中心（跨服务）

| 区块 | 内容 |
|---|---|
| 流水表 | 时间 · 服务 · 模型 · 状态 · 耗时 · tokens；筛选（服务/状态码/模型搜索）|
| 实时 | 轮询/SSE 追加，可暂停滚动 |
| 单条详情 | 该条请求的完整信息（从各服务日志接口取）|

> 不做全局"运行日志"聚合（各服务 stdout 仍在各自服务详情页看），这里只聚合**请求流水**。

## 6. 设置（面板自身）

| 区块 | 内容 |
|---|---|
| 服务注册表 | 四服务的目录/端口/启停命令/健康检查配置，可编辑（改后需重启面板生效项明确标注）|
| 面板偏好 | 主题（浅色/深色/跟随系统）· 数据刷新频率 · 端口 |

| 关于 | 版本 · 各服务版本探测结果 |

## 7. 全局交互与状态设计

| 场景 | 设计 |
|---|---|
| 服务开关（停止） | 点击 → 开关进入 pending「停止中」→ 变更完成。停止属 disruptive 操作：若该服务有进行中请求，二次确认条内联出现（不打断式弹窗）|
| 登录流程（四服务三种：设备码 ×3 + OAuth 回调 ×1） | 统一弹层：步骤指示（发起→等待授权→入池）· 授权链接按钮 · 取消 · 失败原因 |
| 加载 | 表格/卡片骨架屏（形状对齐最终布局）|
| 空态 | 账号空：引导「添加账号」；模型空：引导去模型库；无日志：说明轮询间隔 |
| 错误 | 服务接口报错：区块内错误条 + 重试按钮，不白屏 |
| 数字口径 | 服务停止 = 显示「-」并置灰；冷却中 = 标注预计恢复时间 |
